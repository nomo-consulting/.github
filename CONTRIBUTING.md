# Contributing

Thank you for contributing to a Nomo Consulting repository.

## Before creating an issue

- Search open and closed issues for duplicates.
- Strongly prefer an issue that will produce a code, test, context, documentation, or repository update.
- An operational exception is acceptable when it has a concrete outcome, acceptance criteria, an owner, and durable completion evidence.
- Use the most appropriate issue form and complete every relevant section.
- Never include credentials, secrets, or sensitive client data.

See the [Organization Work Management Standard](docs/work-management-standard.md) for the full policy.

## Working on an issue

- Confirm the outcome, scope, acceptance criteria, and validation before starting.
- Keep the issue's Project status current.
- When blocked, set Status to `Blocked` and populate `Blocked by` and `Blocking reason`.
- Keep the change focused on the agreed issue boundary.

## Opening a pull request

- Use a draft pull request until the change is ready for review.
- Link every fully resolved issue with a separate closing reference, such as `Closes #12`.
- Use `Refs #12` when the pull request supports an issue but does not complete it.
- Include validation evidence, screenshots when applicable, and material risks or rollback steps.
- Update tests, documentation, and canonical context when required.

One pull request may close multiple issues only when the work is inseparable, shares validation and rollback boundaries, and fully satisfies every linked issue.

Repository-specific contribution instructions take precedence when they explicitly override this default.
